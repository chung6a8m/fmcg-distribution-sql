## Phạm vi và nguồn sự thật

AC-21 có 5 checkpoint: `CONFIRMED`, `ALLOC_20K`, `ALLOC_15K`, `OFFER_50K`, `ACCEPT_50K`, mỗi checkpoint so đủ 6 cột (step + AR, CustomerCredit, custody, fund, allocated). AC-20 có 5 checkpoint: `ISSUE`, `EXPENSE`, `OFFER`, `ACCEPT_1`, `ACCEPT_2`, mỗi checkpoint so 5 cột (step + issued, approved expenses, accepted return, outstanding). Số thuộc VND. Không ghi lại numeric expected thành một bộ oracle SQL; runner đọc trực tiếp source JSON lúc chạy.

Mô hình dữ liệu `ac21` có source identity `Command(TenantId,ScopeId,CommandId,Kind,PayloadHash)`. Opening AR có item nguồn riêng; confirmed receipt sinh nguồn credit, confirmed cash sinh custody; allocation làm giảm AR và credit, không chuyển tiền vật lý. OFFER không post sổ; handover ACCEPT ghi hai posting custody âm / fund dương **cùng transaction**. AdvanceIssue/AdvanceExpense/AdvanceOffer/AdvanceAccept trên ledger riêng, không tác động customer balance.

Tất cả commands serialize trên Scope row bằng `SERIALIZABLE`, `UPDLOCK,HOLDLOCK` và kiểm số dư trước effects; source/effects cùng commit/rollback. FK allocation buộc đúng tenant/scope/customer/item và receipt với discriminator `CONFIRMED`. Nạp fault sau khi chèn source, sau allocation hoặc **sau custody âm nhưng trước fund dương** phải rollback sạch. Replay cùng semantic payload trả `REPLAY_ACCEPTED`; khác payload conflict.

## Cách tái kiểm chứng

Trên Windows 2022 hoặc máy dev với SQL Server 2017+ (compatibility >=140), PowerShell/sqlcmd + Windows Integrated Authentication:

```powershell
.\sql\run-tests.ps1 -ServerInstance '(localdb)\MSSQLLocalDB' -IncludeSql03B
```

Chạy `AC-03` 7×13 regression trước; sau đó `ac21` AC-21 + AC-20; assert negative/replay/fault và so 5×6 + 5×5 trường với JSON gốc; guard marker/nonce trước mọi SQL file và trước DROP. Mỗi lần dùng database scratch GUID riêng, evidence JSON ở `sql/test-results/<TestRunId>.json` (không commit). Workflow `.github/workflows/sql-ac21.yml` chạy hai lần và upload artifacts.
